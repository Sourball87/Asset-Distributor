STAGE 2 — MOVEMENT API (after Stage 1 approval)

New endpoint GET /api/experimental/movement (admin-only via requireAdmin):
Query params: distributorId (required), days (default 14), brand (optional), search (optional), limit/offset.

Logic — distributor-generic, not Ingram-hardcoded:
For each product with snapshots for that distributor in the window, order snapshots by snapshot_date and compute per-interval deltas:
  soh_delta = soh - prev_soh; soo_delta = soo - prev_soo; interval_days = date - prev_date
Classify each interval:
  - soh_delta < 0 → outgoing (sell-through estimate = -soh_delta)
  - soh_delta > 0 AND soo_delta < 0 → delivery; masked sales estimate = max(0, -soo_delta - soh_delta)
  - soh_delta > 0 AND soo_delta >= 0 → restock (unexplained inbound)
  - soo_delta > 0 → reorder event (flag separately, doesn't affect sell-through)
Aggregate per product: est_units_out (sum of outgoing + masked sales), units_in, current_soh, current_soo, reorder_flag (any reorder event in window), velocity_per_day (est_units_out / days with coverage), days_of_cover (current_soh / velocity, null if velocity 0).
Response includes per-product daily series (date, soh, soo) for sparklines, plus a data_quality field per product: number of intervals, largest gap in days.
All estimates are floors, not exact sales — name fields est_* accordingly. Add the endpoint to openapi.yaml and regenerate hooks (Orval) per repo convention.
